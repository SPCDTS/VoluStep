# 离散音量曲线设计

## 产品语义

曲线把“按多少次”与“用多少个点塑形”拆为两个独立参数，再在整数按键位置生成 Android 媒体音量目标。

设当前可编辑基准范围为 `minIndex..maxIndex`，跨度 `S = maxIndex - minIndex`：

- `K` 是从最小到最大需要的短按次数，实际按键状态位于 `xₙ = n / K`，共 `K+1` 个；
- `P` 是搭建折线的控制点总数，包含两个固定端点；每个中间控制点保存独立横坐标 `uⱼ`，满足 `0 = u₀ < … < uₚ₋₁ = 1`，不要求均匀；
- 控制点纵轴保存整数 offset `cⱼ`，满足 `c₀ = 0`、`cₚ₋₁ = S`，中间值严格递增；
- 实际第 `n` 次按键先在 `xₙ` 对控制折线 `C(x)` 做线性采样，再用全局最小平方整数投影得到严格递增的目标表 `I[n]`；
- `ΔI[n] = I[n] - I[n-1]` 表示这一按跨越多少个系统 index，也是判断低音量区域是否足够细的主要指标。

严格整数约束基于保存配置的基准跨度，因此 `1 ≤ K ≤ S_basis`、`2 ≤ P ≤ S_basis+1`，但 `P` 与 `K+1` 不要求相等。`P < K+1` 时多个按键状态共享同一折线段；`P > K+1` 时允许保留更细的作者曲线，只在整数按键位置采样。如果当前路由跨度 `S_route` 更小，运行时只采用 `K_effective = min(K, S_route)` 并重新投影实际按键目标；完整 P 点作者折线仍保留，不会被较小路由覆盖。

当系统或耳机把音量外部改到两个配置点之间时，音量加选择第一个严格大于当前 index 的点，音量减选择最后一个严格小于当前 index 的点。这样不会先跳回旧状态，也不会依赖浮点反解的舍入方向。

## 编辑交互

正式版只保留一个主界面，不使用 Tab，也不常驻诊断、历史或精确输入面板：

1. `P` 步进器位于图表上方，`K` 步进器位于 x 轴下方；两者只保留减一、当前值和加一。修改 `K` 不改变折线，修改 `P` 不改变 `K`。
2. 主画布用小型空心点显示 `P` 个控制点，以更小的实心点显示当前路由真正绑定出的整数按键目标。常规路由显示 `K+1` 个；路由跨度小于 `K` 时显示 `K_effective+1` 个，不绘制不存在的中间状态。可见点保持克制，实际触摸命中区域至少为 `32dp`。
3. 中间控制点可同时横向和纵向拖动。x 靠近 `n/K` 时软吸附并显示竖向参考线；y 始终吸附到整数 index，并在拖动时显示水平参考线。控制点不能越过相邻点，两端固定为 `(0, 0)` 与 `(1, S)`。
4. 当前系统音量用绿色水平线、与折线的交点和“当前 n”标签共同标记；水平线对应 y 轴的真实 index，交点给出它在按键轴上的反解位置。
5. 图表下方只有固定长按步进间隔设置，范围 `60…500 ms`、步长 `20 ms`。设备与授权状态收纳在“设备”折叠区；没有 Undo/Redo、精确值编辑、说明菜单或诊断主页面。

辅助能力包括：

- 拖动过程中只更新界面草稿，正常抬手时一次性提交；路由或外部配置变化导致手势取消时回滚到最新来源，不留下未持久化草稿；
- 画布提供完整的 TalkBack 状态描述和控制点选择/移动操作；跨基准路由上的纵向操作按“下一个可表示档位”移动，`K`、`P`、长按间隔和设备开关使用标准 Compose 控件语义；
- 当按键位置密集时减小仅用于展示的小点，但不改变 route-bound 整数目标。

## 点数变化与跨设备投影

修改 `K` 时只保存新的按键采样次数，控制点和值完全不变。运行时在新的 `n/K` 位置采样同一折线，再求满足固定端点和严格递增约束的整数目标序列。

修改 `P` 时保持 `K` 不变。增加点会在现有折线段中插入共线控制点；减少点会优先删除造成形状误差最小的内部点。已有控制点的自由 x 不会被重新均匀化。运行时仍只在均匀的 `n/K` 位置采样，再用确定性的最小平方动态规划得到严格递增的整数目标表，复杂度为 `O(K × S)`。

切换到不同厂商或不同音频路由时使用同一过程把作者折线缩放到实际跨度。设置始终保存完整基准曲线；较小路由只改变运行时小点和 `Δindex` 预览，编辑 K、P 或控制点都不会顺带固化临时降采样。画布纵轴显示当前路由的实际 audio index，控制点编辑再确定性换算回完整基准 offset；运行时小点直接取 route-bound 整数目标。

`rebase()` 仅用于显式建立新的整数编辑基准。它先尝试保留 P 个控制点和曲线形状；如果二次整数量化会改变当前路由已经绑定出的 `K+1` 个目标，则回退为每个实际目标一个控制点，优先保证重建前后的按键行为完全一致。

## 开源交互调研

没有找到一个 Android/Compose 开源控件同时提供“自由控制点、均匀按键采样、双轴吸附、整数纵坐标、严格单调和按键次数语义”。直接引入通用图表库仍需自行实现命中测试、手势事务和约束求解，所以本项目使用 Compose `Canvas` 与标准 Material 控件组合，不增加图表依赖。

可复用的是以下成熟产品模式，而不是直接复制代码：

| 项目 | 可借鉴交互 | 采用方式与许可证边界 |
|---|---|---|
| [Godot CurveEdit](https://github.com/godotengine/godot/blob/master/editor/plugins/curve_editor_plugin.cpp) | 点拖动、吸附、轴锁定、预设、按一次手势记录撤销 | MIT；借鉴手势事务和约束反馈 |
| [AOSP Camera2 ImageCurves](https://android.googlesource.com/platform/packages/apps/Camera2/+/394baebc5579fa9c3f7e09bfbcac7ef666f6c002/src/com/android/gallery3d/filtershow/imageshow/ImageCurves.java) | 移动端触摸命中、拖点与相邻点边界 | Apache-2.0；借鉴移动端直接操控方式 |
| [Audacity Envelope Tool](https://manual.audacityteam.org/man/envelope_tool.html) | 包络线点编辑、视觉反馈 | 文档用于交互参考；GPL 实现不进入本项目 |
| [Ardour Automation](https://manual.ardour.org/mixing/automation/controlling-a-track-with-automation/) | 画笔式自动化、范围选择与精调 | 文档用于交互参考；GPL 实现不进入本项目 |
| [Vico](https://github.com/patrykandpatrick/vico) / [MPAndroidChart](https://github.com/PhilJay/MPAndroidChart) | Android 图表绘制、缩放和标记 | 都擅长展示，但没有本项目需要的受约束点编辑；不引入 |
| [32steps](https://github.com/nulldio/32steps) | 离散步数与响度细分的 Android 实验 | 其额外精度依赖播放 session 上的 DSP 增益，不等同于全局 `STREAM_MUSIC` index 曲线；仅作边界对照 |

`32steps` 一类方案可以通过 [`DynamicsProcessing`](https://developer.android.com/reference/android/media/audiofx/DynamicsProcessing) 在自己掌控的 `AudioTrack`/`MediaPlayer` session 内增加 index 之间的增益级，但本应用控制的是其他应用共同使用的全局媒体音量。把 session DSP 当作全局保证会受到播放器、音效链和厂商实现限制，因此当前版本明确把纵轴保持为系统 audio index。

## 可验证不变量

- v3 持久化同时包含 `K` 以及每个控制点的 `(x, offset)`，P 由控制点数量得到；
- 控制点横坐标自由且严格递增；只有 `K+1` 个按键采样横坐标固定均匀；
- 控制点和实际按键目标都固定端点、使用整数 index 且严格递增；
- 修改 `K` 不改变 `P` 或控制折线；修改 `P` 不改变 `K`；
- x 吸附只改变编辑位置，不改变按键位置的均匀定义；y 吸附始终落在整数 index；
- 当前音量水平标记只反映系统读数，不修改作者曲线；
- 长按在固定延迟后严格按已配置的毫秒间隔前进相邻映射状态；
- 同一路由上的短按只移动到相邻配置状态，外部 index 则按方向选择严格相邻目标；
- 点数变化和跨范围投影结果确定、可重复；
- 固定音量路由没有可用步骤，控制器保持 fail-open；
- Android index 写入回读成功只证明系统接受该 index，不保证蓝牙耳机固件产生可听差异。
