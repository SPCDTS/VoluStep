# 设备与耳机兼容性

VoluStep 使用 Android 公开接口读写媒体音量，支持的档位数量和最小可听音量取决于手机、当前输出路由和耳机。应用会在路由变化后重新探测范围，不按厂商品牌固定为某一档位数量。

## 常见情况

| 情况 | 表现与处理 |
|---|---|
| 最低一档仍然太响 | 曲线只能重新安排现有系统档位，无法降低设备本身的最低可听音量 |
| 不同耳机的档位数量不同 | 应用按当前路由重新生成目标表；较小范围不会覆盖原曲线设置 |
| 相邻系统档位听起来一样 | 蓝牙或耳机固件可能把多个系统值映射为相同响度，回读成功不等于声音一定有差别 |
| 耳机自身按键不沿曲线变化 | 耳机可能直接调整远端音量，不产生手机无障碍服务可接收的 KeyEvent；下一次手机按键会从实际音量继续 |
| USB DAC、HDMI 等输出无法调节 | 输出可能固定音量或需要在外设上调节；应用检测到固定音量时交还系统处理 |
| 后台或熄屏时恢复系统步长 | 检查无障碍连接、主开关和系统后台运行限制，并在相同播放场景下复测 |
| 与其他按键映射服务共存 | 多个服务可能争用同一按键，可暂时关闭其他映射服务，单独检查 VoluStep |

## 后台运行排障

1. 从桌面打开 VoluStep，在“设备”区域检查无障碍状态和当前输出设备，确认主开关已打开。
2. 若只在后台播放时失效，从应用详情检查系统的电池和后台运行策略。HyperOS 可尝试“无限制”，再用相同播放器和耳机复测。
3. 分别检查应用前台、播放器前台、锁屏和熄屏场景；系统重启或强行停止后，重新打开应用并启动映射。
4. 仍有问题时，按 [测试说明](TESTING.md) 记录机型、ROM、输出路由和复现步骤。

应用不显示在最近任务列表中；请从桌面图标返回。停止映射可使用主开关，或系统提供的前台服务管理入口。透明无障碍窗口不能保证所有 ROM 都及时分发按键。

## 已有真机观察

既有测试在 Xiaomi 15、HyperOS、Android 16（API 36）上观察到扬声器和 A2DP 路由提供 `0…150` 的媒体音量范围。应用前台、桌面后台和亮屏锁屏时曾完成单档加减；无媒体播放的熄屏 Doze 场景没有收到可用于映射的按键。

后台实际播放时曾出现无障碍回调延迟，系统先执行默认调节。当前实现会放行过期初始事件并排空迟到尾事件，防止额外写入。更新应用且将省电策略改为“无限制”后的一次对照及时完成了单档调整；由于版本与策略同时变化，不能单独归因于某项设置，也不代表所有 HyperOS 设备均兼容。

这些是特定设备和历史版本下的观察，不是当前版本的完整兼容认证。LE Audio 和其他厂商组合仍需单独验证。

## 路由识别

API 33 及以上通过媒体属性查询输出设备，恰好得到一个设备时标记为 `CONFIRMED`；多个候选或回退选择标记为 `HEURISTIC`。API 28–32 使用 MediaRouter 和已连接设备进行启发式选择。

只有确认路由才建立系统名义 dB 表，该表仅供诊断。曲线始终基于系统整数档位，不使用 dB 推断耳机真实声压或额外音量精度。
